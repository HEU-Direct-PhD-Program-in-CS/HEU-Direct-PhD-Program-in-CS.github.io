❖ Chapter 0x01.1 - 裸机程序模型与 ELF 双重视角

• 裸机程序构建与装载生命周期
C 源码 / 汇编源文件 (.c / .S)
    │  [GCC / AS] 编译汇编生成可重定位目标文件
    ▼
Relocatable Objects (.o, ELF 格式)
    │  [LD 链接器] 按 linker.ld 规划地址与节区合并
    ▼
Executable ELF (.elf)
    │  [HERE 模拟器] 解析 Program Header 并载入 RAM
    ▼
_start (初始 PC: 0x8000_0000) -> main()
核心认知：裸机程序必须自行负责栈指针（sp）初始化、清零 .bss 段以及跳转到 C 语言 main() 入口。
• ELF 规范的双重视角 (Dual Views)
1. 链接视角 (Linking View) —— 以 Section (节) 为单位
• 面向编译器与链接器，由 Section Header Table 描述
• .text (代码指令), .rodata (常量字面量)
• .data (已初始化全局变量), .bss (未初始化零变量)
2. 运行视角 (Execution View) —— 以 Segment (段) 为单位
• 面向 OS 加载器与模拟器，由 Program Header Table 描述
• PT_LOAD 可加载段：记录 p_paddr, p_filesz, p_memsz 及权限
• 权限相同的 Section 会被合并映射至同一 Segment 以节省页开销

❖ Chapter 0x01.2 - 极简 RISC-V 汇编与链接脚本

◈ 极简汇编与 ABI 调用约定示例
.section .text.ENTRY
.globl main
main:
    addi sp, sp, -16
    sd   ra, 8(sp)
    sd   s0, 0(sp)

    li   s0, 0              # s0 为被调用者保存寄存器
1:
    la   a0, msg            # a0 传递字符串首地址
    call printf             # 调用打印函数
    addi s0, s0, 1
    li   t1, 10
    bne  s0, t1, 1b         # 局部标号向前循环 (1b)

    li   a0, 0              # 返回值 a0 = 0
    ld   s0, 0(sp)
    ld   ra, 8(sp)
    addi sp, sp, 16
    ret
ABI: a0-a7 参数/返回; t0-t6 临时; s0-s11 保存; zero 恒零。
◈ 链接脚本 (test_resources/linker.ld)
SECTIONS {
    . = 0x80000000;         /* 物理 RAM 起始地址 */

    .text : {
        /* 确保启动入口 _start 排布在 0x80000000 首地址 */
        *(.text.ENTRY)
        *(.text .text.*)
    }

    .rodata : { *(.rodata .rodata.*) }
    .data   : { *(.data .data.*) }
    .bss    : { 
        _bss_start = .;
        *(.bss .bss.*) 
        _bss_end = .;
    }
    .stack  : { *(.stack) }
}
. (Location Counter)：当前输出地址；脚本规划静态布局，运行时由 boot.S 初始化。

❖ Chapter 0x01.3 - 模拟器装载机制与移植实践

• HERE 模拟器装载 ELF 核心五步
Step 1
校验 ELF Header：验证魔数 0x7F 'E' 'L' 'F'、确认 RV64，读取入口 e_entry。
Step 2
遍历 Program Headers：过滤筛选所有 PT_LOAD 可加载段。
Step 3
搬运数据到 RAM：将文件偏移 p_offset 复制到物理地址 p_paddr。
Step 4
清零 BSS 扩展区：若 p_memsz > p_filesz，将剩余内存清零。
Step 5
初始化 CPU 状态：设置 pc = e_entry (0x8000_0000)，开始执行。

❖ Chapter 0x02.1 - RISC-V 指令编码与 Custom 空间

• 优雅的硬件友好设计理念
1. 固定寄存器位置 (Fixed Register Location)
rs1[19:15], rs2[24:20], rd[11:7] 在所有指令格式中位置恒定不变。硬件在取指后即可并行读取寄存器堆，消除译码延迟！
2. 统一符号位 (Fixed Sign Bit)
所有立即数符号位固定于 bit 31，符号位扩展直接硬连线扇出，无需多路选择器判断。
3. 对称拆分立即数 (Split Immediates)
保证 rs1/rs2 字段位置不受侵占，最大化复用译码多路选择器引脚。
• 6 种标准指令格式 (RV32/64)
R-type: [funct7][rs2][rs1][funct3][rd][opcode] (算术)
I-type: [ imm[11:0] ][rs1][funct3][rd][opcode] (加载)
S-type: [imm1][rs2][rs1][funct3][imm0][opcode] (存储)
B-type: [imm1][rs2][rs1][funct3][imm0][opcode] (分支)
U-type: [ imm[31:12] ][rd][opcode] (高位立即数)
J-type: [ imm[20:1] ][rd][opcode] (无条件跳转)
◈ 官方保留 Custom Opcode 空间
空间名称Opcode (7-bit)二进制表示
custom-00x0B0b0001011
custom-10x2B0b0101011
保证与未来官方标准指令永不冲突，供我们扩展专属硬件指令！

❖ Chapter 0x02.2 - 数据驱动的前端译码架构

• 数据驱动与代码生成 (Build-Time)
无需手写易错位掩码拆解，模拟器采用 JSON 声明：
"padd8": {
  "encoding": "0000000----------000-----0001011",
  "variable_fields": ["rd", "rs1", "rs2"],
  "extension": ["rv_custom0"],
  "match": "0x0b",
  "mask": "0xfe00707f"

• 运行期双级高效译码器 (Runtime)
1. icache (取指译码缓存)

2. funct_decoder (基数表快速查找)
标准规整指令基于 Opcode/funct 建立直接映射，实现 O(1) 极速定位。
3. mask_decoder (掩码匹配)
用于稀疏自定义指令：校验 (raw_instr & mask) == match。
译码输出 DecodeInstr { instr, info, len }。

❖ Chapter 0x03.1 - 模拟器后端执行架构

• 执行引擎主回路 (RVCPU::execute)
1. 函数指针分发路由
通过 get_exec_func(instr) 静态映射表，瞬间路由至对应执行函数。
2. 硬件硬连线强约束：x0 ≡ 0
无论任何指令尝试向 x0 写入何值，执行完毕硬件强制清零：self.reg_file[0] = 0;
3. 异常捕获与冷路径 (Cold Path)
返回 Result<(), Exception>，发生非法指令或对齐故障时触发 Trap。
• 标准流水推进包装器 normal_exec
pub(super) fn normal_exec<F>(
    cpu: &mut RVCPU,
    f: F,
) -> Result<(), Exception>
where
    F: FnOnce(&mut RVCPU) -> Result<(), Exception>,
{
    f(cpu)?;
    cpu.pc = cpu.pc.wrapping_add(4);
    cpu.csr
        .get_by_type_existing::<Minstret>()
        .wrapping_add(1);
    Ok(())
}
精妙设计：当计算发生 Err(Exception) 时，? 立即中断，不会推进 PC，确保 mepc 准确捕获故障现场！

❖ Chapter 0x03.2 - 核心计算抽象与 SIMD 进位隔离

• ExecTrait：纯计算与 CPU 状态解耦
pub trait ExecTrait<OUT, IN = WordType> {
    fn exec(a: IN, b: IN) -> OUT;
}

pub fn exec_arith<F>(
    info: RVInstrInfo,
    cpu: &mut RVCPU,
) -> Result<(), Exception>
where
    F: ExecTrait<Result<WordType, Exception>>,
{
    super::normal_exec(cpu, |cpu| {
        let (rd, rst) = match info {
            RVInstrInfo::R { rs1, rs2, rd } => {
                let (v1, v2) = cpu.reg_file.read(rs1, rs2);
                (rd, F::exec(v1, v2)?)
            }
            // ...
        };
        cpu.reg_file.write(rd, rst);
        Ok(())
    })
}
• Packed-SIMD 关键：进位隔离 (Carry Isolation)
低位溢出 Carry bit 会污染高位，必须物理阻断：
pub struct ExecPadd8;

impl ExecTrait<Result<WordType, Exception>>
    for ExecPadd8
{
    fn exec(
        a: WordType,
        b: WordType,
    ) -> Result<WordType, Exception> {
        let (a_b, b_b) = (
            a.to_le_bytes(),
            b.to_le_bytes(),
        );
        let mut res = [0u8; 8];
        for i in 0..8 {
            res[i] = a_b[i].wrapping_add(b_b[i]);
        }
        Ok(WordType::from_le_bytes(res))
    }
}
支持扩展：8 位饱和加法 saturating_add、单目操作 ExecUnaryTrait。

// 纯软件参考模型 (Golden Model)
static uint32_t golden_padd8(uint32_t a, uint32_t b) {
    uint8_t r0 = (a & 0xFF) + (b & 0xFF);
    uint8_t r1 = ((a>>8)&0xFF) + ((b>>8)&0xFF);
    return ((uint32_t)r0) | (((uint32_t)r1) << 8) | ...;
}

// 循环对比硬件指令与软件参考模型输出

❖ Chapter 0x04.1 - RISC-V 特权级划分与 Trap 分类

• 三级特权级体系 (Privilege Modes)
M-mode (Machine Mode) —— 最高特权级
直接访问所有物理硬件资源；运行 OpenSBI 固件与底层 Trap Monitor。
S-mode (Supervisor Mode) —— 中间特权级
运行操作系统内核（如 Linux Kernel）；具备 Sv39 虚拟内存管理权限。
U-mode (User Mode) —— 最低特权级
运行普通用户态应用程序；受硬件隔离保护，通过 ecall 陷入内核。
• Trap 分类：同步异常 vs 异步中断
分类触发特性典型来源与例子
异常 (Exception)与指令执行同步发生• 非法指令 (IllegalInstruction)
• 地址未对齐 / 缺页异常
• 环境调用 (ecall 系统调用)
中断 (Interrupt)由外部/时钟异步产生• 定时器中断 (MTI/STI)
• 外部设备中断 (MEI/SEI)
• 软件核间中断 (MSI/SSI)
Trap 核心价值：拦截异常、实现特权级跨越、硬件资源保护与多任务分时调度。

❖ Chapter 0x04.2 - 核心 CSR 协同与 Trap 全生命周期

• 关键 CSR 控制状态寄存器
CSR 寄存器功能说明
mstatus全局状态（MIE 中断开关, MPP 前序特权级, MPIE）
mcause最高位指示中断/异常，低位记录具体 Cause ID
mepc记录发生 Trap 时的精确指令 PC 地址
mtval附加信息（如非法访存地址、未识别指令码）
mtvecTrap 处理程序基地址（Direct 或 Vectored 模式）
mip / mie中断挂起位图 (Pending) 与中断使能位图 (Enable)
• Trap 发生与返回流程 (M-Mode 为例)
1. 硬件自动保存现场 (Trap Entry)
• mepc ← pc; mcause ← cause; mtval ← bad_addr
• mstatus.MPP ← 当前特权级; mstatus.MPIE ← mstatus.MIE
• mstatus.MIE ← 0 (关中断); pc ← mtvec.base
2. 软件处理完毕执行 mret 返回
• mstatus.MIE ← mstatus.MPIE; mstatus.MPIE ← 1
• 特权级 ← mstatus.MPP; pc ← mepc (恢复执行现场)

❖ Chapter 0x05.1 - RISC-V 中断拓扑与统一电平采样

• 中断拓扑结构：PLIC vs ACLINT/CLINT
1. 核局部中断 (ACLINT / CLINT)
直连 CPU 核，负责定时器中断（MTIP）与核间软件中断（MSIP）。
2. 平台级外部中断控制器 (PLIC)
收集并仲裁所有外部外设（UART、VirtIO、网卡）中断（MEIP/SEIP）。
3. PLIC 核心机制
Priority, Pending, Enable, Threshold, Claim/Complete 握手机制。
• 统一电平采样接口：PlicDevice
pub trait DeviceTrait: 'static {
    fn read(&mut self, addr: WordType, len: u32)
        -> Result<u64, MemError>;
    fn write(&mut self, addr: WordType, len: u32, data: u64)
        -> Result<(), MemError>;
    fn sync(&mut self);
}

pub trait PlicDevice: DeviceTrait {
    /// 返回当前中断引脚的绝对电平状态 (Level-Triggered)
    fn irq_level(&mut self) -> bool;
}
集中采样：PLIC 在 Claim/Complete 周期自动调用 irq_level()，杜绝中断丢失！

❖ Chapter 0x05.2 - 异步运行时与内存可见性屏障

• TaskSpawner 与 Tokio 异步运行时
CPU 主循环高速推进，耗时外设任务卸载至后台异步运行时：
pub fn spawn_task(&self, task: TaskFuture) {
    self.spawn.try_send(task).expect("Failed to spawn");
}
SampleTimer 范例：CPU 写 MMIO 触发异步等待，到期后原子置位 irq_pending，主线程零延迟！
• 跨线程内存屏障 (Acquire-Release 语义)
// 1. 后台异步写线程 (Release 语义)：确保 RAM 写入先于 isr 对外可见
self.isr.fetch_or(1, Ordering::Release);

// 2. 主线程 PLIC 采样 (Acquire 语义)：建立 Synchronizes-With 屏障
impl PlicDevice for VirtIODevice {
    fn irq_level(&mut self) -> bool {
        self.isr.load(Ordering::Acquire) != 0
    }
}
安全保证：Release 写与 Acquire 读配对，保证 CPU 响应中断时共享 RAM 数据已就绪！

❖ Chapter 0x05.3 - VirtIO 半虚拟化与系统外设开发

• VirtIO 规范与 Split Virtqueue 结构
半虚拟化让 Guest 与 Host 共享内存环形队列，批量请求仅敲一次 Doorbell：
1. Descriptor Table：记录缓冲区物理地址 paddr、长度 len 与 flags。
2. Available Ring：Guest 写 / Host 读，通知 Host 有新待处理请求。
3. Used Ring：Host 写 / Guest 读，Host 完成 I/O 后归还 Buffer 并触发中断。

❖ Chapter 0x06.1 - Linux 内核启动链路与设备树 DTS

• Linux 全系统启动链路 (Boot Chain)
1. 复位引导 (Emu → OpenSBI @ M-Mode)
PC 指向 0x80000000，a0=HartID(0)，a1=DTB 地址；OpenSBI 完成底层硬件初始化与 SBI 服务注册。

3. 根文件系统挂载 (Kernel → Init Process @ U-Mode)
挂载 Rootfs，切换至 U-mode 执行首个进程 /sbin/init 进入 Shell。

❖ Chapter 0x07.1 - SIMD 原理与 RISC-V V 扩展架构

• SIMD 概念与端侧 AI 算力诉求
标量 (Scalar) vs SIMD (单指令多数据)：单条向量指令（如 vadd.vv）可同时对数十乃至数百个元素并行计算。
端侧 AI 核心加速引擎：MobileNet 图像分类、Whisper 语音识别、本地大模型推理中，绝大部分算力集中于 GEMM 矩阵乘法、卷积与点积，SIMD 将计算吞吐提升数倍至数百倍！
• RISC-V V 扩展：VLA 矢量长度无关架构
不同于 x86 AVX (固定 128/256/512 位)，RVV 采用 VLA (Vector Length Agnostic)：
1. 写一次代码，到处高效运行
同一二进制无论在 128-bit 嵌入式 MCU 还是 4096-bit 超算上均可自适应发挥极致性能。
2. 关键控制 CSR 寄存器
• vtype: SEW (8/16/32/64), LMUL (1/2/4/8)
• vl: 当前实际处理元素个数，由 vsetvli 动态计算
模拟器当前已支持 RVV 1.0 标准整型向量指令集！

❖ Chapter 0x07.2 - 编译器对 RISC-V 向量扩展的优化

• LLVM 向量化引擎与专属 Pass 优化
1. RISCVInsertVSETVLI Pass (状态机冗余消除)
遍历控制流图进行数据流分析，消除相邻指令冗余的 vsetvli 配置，并将其提升至循环前驱块（Loop Hoisting），实现循环内纯计算零开销。
2. Tail-Agnostic (ta) 策略优化
指示硬件不关心未激活尾部元素，打破寄存器重命名虚假数据依赖，极大加速乱序发射。
• Tail-Folding：消灭标量尾循环
# a0=a, a1=b, a2=c, a3=N (AVL)
.LBB0_1:
    # 动态申请本次计算元素个数 t0 = min(a3, VLMAX)
    vsetvli  t0, a3, e32, m1, ta, ma
    vle32.v  v1, (a0)           # 向量加载 a[i]
    vle32.v  v2, (a1)           # 向量加载 b[i]
    vadd.vv  v3, v1, v2         # 向量加法
    vse32.v  v3, (a2)           # 向量存储 c[i]
    slli     t1, t0, 2          # 字节偏移 = t0 * 4
    add      a0, a0, t1
    add      a1, a1, t1
    add      a2, a2, t1
    sub      a3, a3, t0         # 剩余元素数 N -= t0
    bnez     a3, .LBB0_1        # 尾部按实际余数安全计算！
代码极其精炼，无任何冗余标量分支！
