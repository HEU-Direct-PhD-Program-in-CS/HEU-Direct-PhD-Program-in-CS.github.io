我的理解:

指令集定义了CPU这个状态机(图灵机)的行为。就像C语言手册规定了C语言编译器的行为。

如何理解 CPU 是一个状态机

在编译原理课上我们学过 NFA(不确定的有穷状态自动机) 和 DFA(有穷状态自动机).

    状态集合: $S = \{S_1, S_2, ...\}$;
    激励事件;
    状态转移规则: $next: S * E -> S$;
    初始状态: $S_0$;

如何理解 CPU 是一个状态机

理论计算机的开端: 图灵机.
从下图我们很容易看出: 图灵机由输入的 program 和一条无限长的纸带组成.
输入的program 可以看作是激励(input), 纸带的内容和读写头的位置就可以看作是状态(state).

如何理解 CPU 是一个状态机

回到我们的cpu, 举个例子:

• C 源码 (a.c) 

int f() {
    int a = 1;
    int b = 2;
    return a + b;
}
• LLVM IR (a.ll) 

define dso_local i32 @f() #0 {
  %1 = alloca i32, align 4
  %2 = alloca i32, align 4
  store i32 1, ptr %1, align 4
  store i32 2, ptr %2, align 4
  %3 = load i32, ptr %1, align 4
  %4 = load i32, ptr %2, align 4
  %5 = add nsw i32 %3, %4
  ret i32 %5
}

假设我们的 CPU 只有5个寄存器和一个 pc 寄存器: {r1-r5; pc}，指令长度为 1

那么忽略掉 alloc 之后的状态转移如下：

(0, 0, 0, 0, 0, 3)

--[store]-> (1, 0, 0, 0, 0, 4) --[store]-> (1, 2, 0, 0, 0, 5)

---[load]-> (1, 2, 1, 0, 0, 6) ---[load]-> (1, 2, 1, 2, 0, 7)

----[add]-> (1, 2, 1, 2, 3, 8) ----[ret]-> output 3

CPU 是一个自动机

1. 指令集还定义了 CPU 这个状态机的激励.
2. 指令集定义了 CPU 这个状态机的状态集合.
3. 同一指令集, 可以有不同的实现(微架构).

从这个状态机的视角来看, CPU 的性能优化无外乎就是对状态和激励的优化. 其中状态集合的数量影响性能的强弱和成本, 激励的转移延迟影响频率的高低

RISC

RISC (Reduced Instruction Set Collection)

根据我们刚才对 CPU 的理解, Reduced 的内容本质是减少状态和激励的数量来优化设计.

常见的设计理念包括:

    1. 指令定长, 方便cpu前端设计;
    2. 指令数量少, 方便cpu后端设计;
    3. 简化寄存器和内存控制器的设计(不支持非对齐访存, 较为宽松的内存一致性要求);
    4. 减少访存的方式, 方便 访存执行器 的设计

为什么 x86 是CISC

x86 的 MOV 指令:


; 1. 寄存器 ← 寄存器
mov rax, rbx    ; 64位
mov eax, edx    ; 32位
mov al, bl      ; 8位

; 2. 寄存器 ← 立即数
mov rax, 42
mov eax, 0x1234
mov al, 'A'

; 3. 内存 ← 寄存器
mov [rax], rbx
mov DWORD PTR [rbp-4], eax

; 4. 寄存器 ← 内存
mov rax, [rbx]
mov eax, DWORD PTR [rbp+8]

; 5. 内存 ← 立即数
mov QWORD PTR [rsp], 0
mov BYTE PTR [rdi], 1

ARM 真的是 RISC 吗?

  • ARMv7 中的: ldmiaeq SP!, {R0-R12, PC}^指令:
    • LoaD Mulpitle, Increment-Address, on EQual
    • 需要从内存中读取14个数据, 更新13个寄存器
    • 其中包括PC寄存器, 相当于间接跳转
    • 如果条件码eq不满足, 则不进行任何操作
  • 显然直接执行这一指令会和别的指令的执行时间有非常大的区别, 这会颠覆现有的流水线设计.
  • 因此ARMv7选用了与x86类似的微码的方式处理这类指令😂
  • 还觉得ARM是RISC指令集吗? (ARM-v8重新设计, 去掉了这类指令)

指令集模块化

riscv包含30+个指令扩展模块, 其中常用的包括 I, M, A, D, F, C, B(Bit), H(Hypervision), K(Cryptography), V(Vector)

 

其中常用的 IMAFD 和 Zicsr + Zifencei 通用计算扩展组成成了 G 扩展

 

优势:

  1. 方便芯片设计者根据自己的需求选择合适的扩展, 设计出适合自己应用场景的CPU.
    • 例如嵌入式设备可以选择 IMA + Zicsr + Zifencei + C, 设计出面积小, 功耗低的CPU;
    • 通用高性能计算可以选择 GCBHKV, 设计出高性能的CPU;
    • 由于 riscv 开源的性质, 可以方便的添加自己需要的扩展, 设计出适合自己应用场景的CPU;
  2. 设计CPU时, 可以将各个执行模块解耦, 方便设计和单元验证, 实现敏捷开发;
  3. 易于长期扩展和兼容性:
    • armv7 用完了指令空间后为了添加 thumb 和 thumb2 扩展, 不得已添加了两个控制标志位, 用来区分 thumb 和普通指令模式.
    • 而 riscv 可以通过不使用旧的扩展, 来实现为新指令集腾出空间的作用, 并且通过编译技术的支撑, 可以很轻易的为不同扩展的 riscv cpu 生成代码.
  4. x86的短指令 50% 以上是不常用指令, 而 riscv 的 C 扩展使用频率非常高, 能做到体积比 x86 更小.

指令格式(1)

  • 指令格式固定
    • opcode/func3/func7的位置固定.
    • rs1/rs2/rd 位置固定, 可以减少一个选择器.
  • 指令长度固定(除了C扩展)

指令格式(2)

标识一条指令, 依次通过 opcode -> func3 -> func7 三级:

  • opcode: 指令的类型, 决定了指令的基本操作, 以及指令的格式: 如寄存器算数运算, 分支运算, store, load...;
  • func3: 决定了指令的具体操作: 算数{加/减/乘/除}, 访存(byte/half_word/word);
  • func7: 指令的变体;

开源指令集

  • 允许cpu厂商向指令集添加自定义指令.
    • 对于IoT厂商, 可以使用单独的指令控制外设, 规避mmap的延迟.
    • 对于高性能厂商, 可以添加更多的SIMD指令和访存指令, 提高性能, 同时可以继承原有的riscv生态.
  • 不需要授权费用, 相比arm在成本上更有优势.
    • 截至2024年 riscv 出货量: 百亿颗;
    • 2025年全年销售额超过50亿, arm为300亿, 已经形成追赶态势. 并且在中国市场, riscv占比更高, 且已经出现 riscv 高性能云服务器集群商业化落地的案例.

寄存器模型

  • riscv 将寄存器区分为了 a, s, t 三类：函数调用时，t 寄存器由调用者保存，s 寄存器由被调用者保存，a 寄存器用于传递参数。通过 32 个通用寄存器（相比 ARM/x86 的 16 个）简化了编译器寄存器调度。
  • 将 x0 (zero) 寄存器硬连线为 0，从而简化了与立即数 0 比较的指令，减少指令空间占用：
    • C 源码 (compare_zero.c)
    
int is_zero(int a) {
    if (a == 0) {
        return 1;
    } else {
        return 0;
    }
}
    • RISC-V 汇编 (compare_zero.S)
    
0000000000000000 <is_zero>:
  14: sw    a5, -20(s0)
  18: lw    a5, -20(s0)
  20: bne   a5, zero, 2c <.L2>  # 与 zero(x0) 比较
  24: addi  a5, zero, 1         # 利用 zero 写入立即数 1

000000000000002c <.L2>:
  2c: addi  a5, zero, 0         # 利用 zero 写入立即数 0

RISC-V 的定位在哪

为什么x86依旧占领高性能CPU领域

  • x86 CPU 设计引入了 微指令架构, 将三千多条指令映射为几白条微指令, 这些微指令都是 risc-like 的, 因此大大降低了 流水线 设计的复杂度.
  • x86 的单条指令功能密度更高, 一条 x86 指令平均能产生 3-4 条微指令, 通过并行decoder 和 微操作缓存, 可以实现 更高的指令吞吐率.
  • x86 指令本身的兼容性极强, 对于老旧软件的支持非常好.

RISC-V的机会

  • riscv的极简理念, 导致cpu的性能不占优势, 但是, 随着 AI和异构计算 的发展, riscv的轻量/敏捷优势可以更方便的与NPU/TPU等协处理器协同工作, 通过专用协处理器来弥补指令集的不足, 从而实现更高的性能.
  • riscv的开源特性, 可以方便的添加自定义指令, 通过一些 "野路子" 实现更低的 io 延迟.
  • 极简的设计可以让 riscv cpu 的成本更低, 开发更灵活, 适合大规模部署在边缘侧的设备中.

RISC-V 发展近况

  • riscv 因其开源的特性, 基本霸占了 GPU, NPU, 屏幕主控, 磁盘主控 等协处理器的主控生态, 各家可以根据自身需要添加少量场景专用指令, 固件直接可以使用riscv开发, 灵活性极高.
  • riscv 碎片化问题在 2023 年末得到了关注, rva 和 rvb 标准指令扩展包被制定出来, 分别针对高性能计算和嵌入式linux场景, 方便硬件设计与软件适配. 同时还行制定 rvm 标准扩展指令包, 用于MCU场景.
  • 面对如今AI爆火, 传统的算力都是 host + device 的模式, 会产生通讯开销, 总线设计复杂, 任务依赖中断推动. 而 riscv 希望避开 The Wheel of Reincarnation, 提供一个 self-host 的解决方案, 于是 针对不同场景, 提出了四类不同的 矩阵(加速)扩展, 预期在明年二季度, 这四个扩展都会冻结并发布.
  • 安全领域, riscv 也在稳步推进芯片安全扩展, CHIRY 等扩展提供的更强的应用层内存安全保证
  • 同时, 由于32位指令空间基本已经消耗殆尽, 目前已经重启了 48 位指令空间的编码工作.
