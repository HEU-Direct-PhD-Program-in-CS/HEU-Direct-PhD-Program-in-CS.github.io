# RISC-V 指令集

## 指令集是什么

课本上通常会给一个抽象的定义：

```
指令集是软件与硬件之间的接口。
```

但是怎么理解 `接口`, 这个软件和硬件又指的是什么?

对于一个 同属于 `x86_64` 的 `cpu`, 为什么性能不一样, 还区分 `AMD Zen4/5`, `Inter Lunar Lack/Arrow Lack`, `armv8` 也区分 `a75/a77` 等不同架构, 这些架构有什么区别.

引出了一个问题: 指令集和 `cpu` 的关系.

人话：指令集定义了CPU这个状态机的行为。就像C语言手册规定了C语言编译器的行为。


### 如何理解 CPU 是一个自动机

编译原理我们学了自动机，状态机一般指的就是有限状态自动机。

DFA的状态是当前接受的子序列, 激励是下一个token. 那么对于 cpu/图灵机 什么是激励，什么是状态. 指令集就约束了这一问题。指令就是激励，整个存储体系就是状态集合。

1. Johnson 加法器。
2. 通过 C语言程序 理解。  

理解:

1. 指令集还定义了 CPU 这个状态机的激励.
2. 指令集定义了 CPU 这个状态机的状态集合.
3. 同一指令集, 可以有不同的实现(微架构).


### 指令集约束了哪些实现

除了最基础的指令类型，还包括：
1. 输入输出
2. 系统状态
3. 中断异常
4. 虚存管理
5. 内存模型

## `riscv`

### 先说说 `risc`

`RISC（Reduced Instruction Set Collection）` 精简指令集。

指令集的精简体现在：
1. 指令基本定长。
2. 指令数量相对少 -> 单条指令的功能相对弱。
3. 简化寄存器和内存控制器的设计

优势：
1. CPU设计简单 -> 芯片面积小，成本低。
2. 分支预测，调度更容易 -> 超线程。


### 指令模块化

优势:

1. 方便芯片设计者根据自己的需求选择合适的扩展, 设计出适合自己应用场景的CPU.
    1. 例如嵌入式设备可以选择 IMA + Zicsr + Zifencei + C, 设计出面积小, 功耗低的CPU;
    1. 通用高性能计算可以选择 GCBHKV, 设计出高性能的CPU;
    1. 由于 riscv 开源的性质, 可以方便的添加自己需要的扩展, 设计出适合自己应用场景的CPU;
2. 设计CPU时, 可以将各个执行模块解耦, 方便设计和单元验证, 实现敏捷开发;
3. 易于长期扩展和兼容性:
    1. armv7 用完了指令空间后为了添加 thumb 和 thumb2 扩展, 不得已添加了两个控制标志位, 用来区分 thumb 和普通指令模式.
    1. 而 riscv 可以通过不使用旧的扩展, 来实现为新指令集腾出空间的作用, 并且通过编译技术的支撑, 可以很轻易的为不同扩展的 riscv cpu 生成代码.
4. x86的短指令 50% 以上是不常用指令, 而 riscv 的 C 扩展使用频率非常高, 能做到体积比 x86 更小.
